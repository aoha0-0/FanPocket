# FanPocket (ファンポケット)

> **「大切な推し活予定を、ポケットに。」**

チケットの申し込みやグッズ販売などの情報をURLと一緒に保存し、
開始・締切を管理して、大切なタイミングを通知でお知らせする推し活特化型スケジュール管理アプリです。

---

## 💡 サービス概要

FanPocketは、チケットの申し込みやグッズ販売など、忘れたくない推し活予定をまとめて管理するためのWebアプリです。

推し活では、情報を見つけてもすぐに申し込みや購入ができるとは限りません。
「あとでやろう」と思った予定を一度FanPocketに預けておくことで、必要なタイミングに思い出し、行動につなげられることを目指しています。

また、仕事や日常の予定と混ざらない「推し活だけの場所」にすることで、
大切な推しの予定に集中できる空間を大切にしています。

### 🎯 解決したい課題

- **後回しによる機会損失の防止:** 受注販売や数量限定グッズなど、「あとで」と思っているうちに期限を過ぎてしまう買い逃し・申し込み忘れを防ぎます。
- **手入力による日付ミスの軽減:** URLからタイトルや日時候補を取得する入力補助によって、予定登録の手間や日付の入力ミスを減らします。
- **推し活予定の埋没を防止:** 仕事や日常の予定とは分けて推し活だけを管理することで、大切な開始・締切を見つけやすくします。

---

### 💭 開発背景

私自身、多ジャンルの推し活を日常的に楽しんでいます。
情報は公式XやLINE、各種サイトから収集していましたが、支払いのタイミングなどの理由から、その場ですぐに申し込んだり購入したりできず、「あとで申し込もう」「あとで買おう」と後回しにすることが多くありました。

ある時、Xのポストをきっかけに、気になっていたグッズの受注販売期間がすでに終了していたことに気づきました。

「発売を知っていたのに、情報も見ていたのに、後回しにしたまま忘れて買えなかった」

この経験から、問題は「情報を知らなかったこと」ではなく、**知った情報をあとから行動につなげられなかったこと**にあると感じました。

この「忘れてしまうもったいなさ」を減らし、大切な申し込みや購入の機会を逃さず、安心して推し活を楽しめるようにしたい。
そう考えたことが、FanPocketを開発したきっかけです。

### 🌱 なぜ「推し活専用」なのか

カレンダーアプリでもURLや予定を登録できますが、
「申し込み・購入が完了したか」という状態と通知は連動しないため、
対応後は自分で通知を変更・削除する必要があります。

また、一般的なToDoアプリでは、仕事や日常生活のタスクと推し活の予定が同じ場所に並びます。

私にとって推し活は、好きなものを楽しむだけでなく、日常でつらいことがあったときに元気や勇気をもらえる大切な時間でもあります。
だからこそ、その中に仕事や日常のタスクを混在させるのではなく、**「好き」な予定だけを安心して管理できる場所**を作りたいと考えました。

FanPocketでは、推し活の予定だけをまとめ、対応が完了した予定は通知対象から外すことで、
「今、確認する必要がある推し活予定」に集中できるようにしています。

チケットの申し込みやグッズ販売など、これから対応したい推し活予定を一覧で管理できます。

開始日時・締切日時・URL・メモなどをまとめて登録でき、開始・締切までの期間に応じた色分けによって、今確認したい予定をひと目で把握できるようにしています。

対応が完了した予定や期限を過ぎた予定は「これまでの足跡」として分けて表示し、これから対応する予定に集中できるようにしています。


### 🔔 「あとで」を忘れないための通知

FanPocketでは、予定を登録するだけでなく、
「あとで申し込もう」「あとで買おう」を実際の行動につなげることを大切にしています。

そのため、メール・LINE・アプリ内通知の3つを、それぞれ異なる役割で活用しています。

| 📧 メール通知 | 💬 LINE通知 | 🔔 アプリ内通知 |
| :---: | :---: | :---: |
| <img src="https://i.gyazo.com/53fed35e6d63d371675435eaf4a4e0c0.png" width="220" alt="メール通知"> | <img src="https://i.gyazo.com/1476cbe9cb60fa041512f6ef167358cf.png" width="220" alt="LINE通知"> | <img src="https://i.gyazo.com/11d78ecde0b6d3c953bd5ef4ca6ff71e.png" width="220" alt="アプリ内通知"> |
| **事前確認** | **直前の行動** | **あとから確認** |
| 締切3日前・前日・当日、開始当日にお知らせ | 開始10分前・締切3時間前にお知らせ | 届いたお知らせをアプリ内に保存 |

対応が完了した予定は通知対象から外し、まだ対応が必要な予定に絞ってリマインドします。

また、メール・LINEそれぞれの通知タイミングは設定画面から個別にON / OFFを変更できます。

### 🔗 URLから入力をサポート

公式サイトなどのURLを入力すると、ページタイトルを自動取得します。

さらに、ページ内のテキストから日時候補を抽出し、開始・締切日時の入力をサポートします。

自動取得ができない場合も手入力できるようにし、取得結果に依存せず予定を登録できる設計にしています。


### 🏷️ タグ・受付種別で予定を整理

予定が増えても過去の情報を探しやすいよう、アーティスト名やグループ名などを自由に設定できるタグ機能を実装しています。

タグで絞り込むことで、「以前このグループの申し込みをしたか」など、過去の予定をあとから確認できます。

また、「抽選」「先着」「受注販売」など、推し活でよく使う受付種別をあらかじめ選択肢として用意しています。
「FC先行」などの詳細情報と組み合わせることで、予定の内容を分かりやすく表示しながら、登録時の入力負担を減らしています。


### 🔐 Google・LINEによるSNS認証

メールアドレス・パスワードによる認証に加えて、Google・LINEを利用した新規登録・ログインに対応しています。

Googleログインは、アカウント作成時の入力負担を減らし、より手軽にFanPocketを使い始められるようにするため導入しました。

LINEはログイン手段としてだけでなく、FanPocketの核となる直前通知にも活用しています。
LINEアカウントとの連携情報を通知機能にも利用することで、認証から通知まで一貫した体験になるよう設計しています。

また、メールアドレスで登録したユーザーも、設定画面からGoogle・LINEアカウントを後から連携できます。


### 📱 ジャンルを問わず使いやすいUI/UX

特定のジャンルや性別に偏らず、幅広いユーザーが使いやすいよう、水色をベースとしたシンプルでやわらかなデザインに統一しています。

スマートフォンでは画面下部、PCではサイドメニューに主要なナビゲーションを配置し、予定一覧・設定へアクセスしやすい導線を設計しました。

また、編集画面からは元の詳細画面へ戻れるなど、操作の流れに沿った戻り先を用意しています。

初回利用時にはウェルカムナビゲーションを表示し、使い方ガイドも用意することで、初めて利用するユーザーでも予定登録まで迷いにくいよう工夫しています。

## 💎 こだわり・技術的工夫

### 🔔 「あとで」を行動につなげる通知基盤

FanPocketでは、「情報を知っていたのに、あとで対応しようと思って忘れてしまった」という自身の経験から、通知機能をアプリの核として設計しています。

通知は役割に応じて、**メール・LINE・アプリ内通知**の3種類に分けています。

- **メール通知：事前確認**
  - 締切3日前
  - 締切前日
  - 締切当日
  - 開始当日
- **LINE通知：直前の行動**
  - 開始10分前
  - 締切3時間前
- **アプリ内通知：あとから確認**
  - 発生した通知をアプリ内にも残し、後から確認可能

#### 通知の実行

Google Apps Script（GAS）から定期的に通知用エンドポイントへリクエストを送り、
Rails側で現在時刻に応じて必要な通知処理を実行しています。

```text
Google Apps Script
        ↓
POST /internal/notifications
        ↓
Internal::NotificationsController
        ↓
NotificationService
        ├─ MorningNotificationService
        │    └─ 当日締切・当日開始
        │
        ├─ NightNotificationService
        │    └─ 締切3日前・締切前日
        │
        └─ RealtimeLineNotificationService
             └─ 開始10分前・締切3時間前
```

朝・夜のメール通知はRails側で時刻を判定し、LINEの直前通知は定期実行のたびに対象となる予定があるかを確認します。

#### 重複通知を防ぐ仕組み

定期的に通知処理を実行しても同じ通知が繰り返し送信されないよう、
`notification_deliveries` テーブルに送信履歴を記録しています。

`watchlist_id`・`channel`・`notification_type` の組み合わせには一意制約を設定し、
アプリケーション側の判定だけでなく、データベース側でも重複通知を防止しています。

また、対応済みの予定は通知対象から除外し、
まだ対応が必要な予定だけに通知するよう設計しています。

### 🔗 URLからのタイトル・日付抽出で入力負担を軽減

予定登録時にURLを貼り付けて「タイトル取得」ボタンを押すと、
MetaInspectorを利用してページタイトルを取得します。

日時については、Nokogiriでページ本文を解析し、
不要な `script`・`style` 要素を除外したテキストを `DateExtractorService` へ渡しています。

`DateExtractorService` では、正規表現を使って単発の日付や期間表記を抽出し、
曜日の除去や年・時刻の補完などを行ったうえで、開始・締切日時の候補としてフォームに表示します。
期間表記は開始・締切に分けて候補として扱います。

自動取得できない場合でも手入力できるようにし、
外部サイトの構造に依存しすぎない入力補助として設計しています。

### 🎨 推し活に集中できるUI/UX

推し活はジャンルもユーザーもさまざまであるため、特定のジャンルや性別のイメージに偏らず使えるデザインを意識しました。

ベースカラーには、白だけでは物足りなさを感じる一方で、特定のイメージに寄りすぎない色として水色を採用し、アプリ全体をやわらかく統一しています。

#### 視覚的に予定の状態がわかる一覧

予定一覧では「信号機」のように、色を見るだけでも予定の状態を把握できることを意識しています。

- 🟢 **黄緑：開始が近い予定**
- 🟡 **黄色：締切が近づいている予定**
- 🩷 **ピンク：締切が目前の予定**
- 🔵 **水色：通常の予定**
- ⚪ **グレー：終了した予定**

「もうすぐ始まる」「締切が近い」といった状態を文字だけに頼らず、視覚的にも判断できるようにしました。

#### デバイスに合わせたナビゲーション

主要な画面へ移動しやすいよう共通ナビゲーションを設けています。

スマートフォンでは操作しやすい画面下部、PCでは画面を広く使えるサイドメニューとして配置し、デバイスに合わせて見た目と操作性の両方を調整しました。

また、編集画面から元の詳細画面へ戻れる導線を用意するなど、操作途中でも迷いにくい画面遷移を意識しています。

#### 初めてでも使い方がわかる導線

開発中に「初めて一覧画面を見たとき、何をすればよいかわかりにくい」という意見をもらったことから、初回利用時にウェルカムナビゲーションを表示するよう改善しました。

さらに、FanPocketでできることや予定の登録方法、通知・色分けの意味などを確認できる使い方ガイドを用意し、アプリ全体のデザインや雰囲気に合わせて、初めて利用するユーザーにも伝わりやすいページを目指しました。

## 📈 今後の展望・発展性

FanPocketを実際に利用してもらいながら、ユーザーがより安心して長く使えるサービスへ改善していきたいと考えています。

### 🔍 予定を探しやすくする検索機能

現在はタグを利用して予定を分類できますが、登録する予定が増えた場合でも、過去・現在の予定から目的の情報をすぐに見つけられるよう、タイトルなどを対象とした検索機能の追加を検討しています。

### 📩 お問い合わせ機能

現在はアプリ内にお問い合わせ手段がないため、不具合や利用上の疑問などをユーザーから受け取れるお問い合わせ機能の追加を検討しています。

今後も実際の利用状況やフィードバックをもとに、必要な機能を見極めながら改善を続けていく予定です。
